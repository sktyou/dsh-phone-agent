# DSH Phone Agent 测试台

一个 Web 页面,用来调试手机的各个能力。**这是开发工具,不是产品的一部分**。

同一个页面有**两种托管方式**:

| 方式 | 地址 | 适用 |
|---|---|---|
| **手机托管** | `http://<手机IP>:7913/` | 任何设备都能开,**不依赖 PC** |
| PC 托管 | `http://127.0.0.1:8099/` | 改页面即时刷新,不用重装 App |

**两种方式页面完全一样** —— 页面用的是相对路径(`/rpc`、`/shot`),所以同一份
HTML 在两边都能跑。

## ⚠️ 为什么不放在 7912

`7912` 说的是**裸 TCP + 行分隔 JSON**,**不是 HTTP**。浏览器发的是 HTTP 请求,
那个端口不认识,直接 `http://192.168.12.138:7912/tools` 只会得到看不懂的字节。

所以 HTTP 用**独立端口 7913**,它在手机内部把请求转发到 7912:

```
浏览器 ──HTTP──> 7913 (WebConsole) ──裸TCP──> 7912 (ControlServer)
```

转发而不是直接调用命令处理,是为了**只有一份命令实现** —— 页面看到的校验、
错误码、行为和其他任何客户端完全一致。

## 手机托管(推荐日常使用)

App 启动控制服务时会**自动**把页面服务也拉起来,手机上打开:

```
http://192.168.12.138:7913/
```

地址也显示在 App 首页的地址卡片里。不需要电脑,不需要 adb。

## PC 托管(改页面时用)

```powershell
node tools/webui/server.mjs
# 浏览器打开 http://127.0.0.1:8099
```

改 `tools/webui/index.html` 存盘刷新即可。**改完记得同步到 App**:

```powershell
copy tools\webui\index.html android\app\src\main\assets\webui\index.html
```

可选参数:`--host 192.168.12.138 --port 7912 --web 8099`

## 页面能做什么

### 左栏:手机截屏

- **单击** → `tap`,坐标自动换算成手机像素
- **按住拖动** → `swipe`,自动算距离并按距离推算时长
- **滚轮** → `scroll`

底部实时显示**图像尺寸 / 手机尺寸 / 指针坐标 / 拖拽起止点与距离**。

> 坐标换算是这个页面存在的核心理由。截屏是缩放显示(默认 50%),肉眼无法直接
> 得知对应的手机坐标;这里用渲染后的元素框换算,所以不管怎么缩放都是准的。

### 右栏:三个面板

**节点树** —— 显示当前界面的无障碍节点。**只列出有用的节点**(有文字、有 id、
可点击/可滚动/可编辑),因为一个页面动辄十几层 FrameLayout,全渲染出来会把手
机截图上真正重要的那几个节点埋掉。缩进仍按真实深度,所以层级关系还在。

**选中详情** —— 点击任一节点后,这里显示完整属性,并**自动生成可用选择器**:

```
viewId       {"viewId":"com.xx:id/btn"}
text(精确)    {"text":"登录"}
textContains {"textContains":"登录"}
class+可点     {"cls":"android.widget.Button","clickable":true}
```

点选择器即复制,可以直接贴进命令。还有个按钮可以**直接点击该节点中心**。

**命令日志** —— 每条命令的成功/失败、耗时、参数。排查"为什么这一步没生效"时
先看这里。

### 顶栏快捷操作

刷新截屏 · 自动刷新(1.5s) · 缩放 · 设备信息 · 节点树 · 滚动识别 ·
返回/桌面 · 输入文字/提交/清空 · findtext / OCR

## 注意

- 服务**只监听 127.0.0.1**,不对外暴露。
- 页面每次截图都是一次完整往返,自动刷新别开太频繁。
- 手机侧内存紧张时请求会变慢甚至超时,先确认 `ping` 延迟。
